# PrismWave 全页面覆盖式导航转场设计

## 目标

PrismWave 的所有页面导航统一采用覆盖式转场：新页面从内容区右侧进入，并在 280ms 内向左移动至最终位置，完整覆盖保持静止的旧页面。左侧导航、标题栏、底部播放器和队列浮层不参与页面位移。

## 已确认的交互规则

- 所有一级页面、二级详情页和返回导航使用同一方向：始终从右向左。
- 旧页面在转场期间保持原位，不平移、不缩放、不变暗。
- 新页面移动距离等于当前内容宿主的实际宽度。
- 动画时长固定为 280ms，使用 Fluent 风格的前快后慢减速曲线。
- 首次启动直接显示初始页面，不播放转场。
- 导航到当前页面时不重复播放转场。
- 弹窗、菜单、QueuePane 和底部播放器状态变化不触发页面转场。
- `LowEffects` 和 Windows 系统动画开关不禁用该导航反馈；它们继续用于控制模糊、歌词和封面等高成本特效。

## 视觉边界

- 转场只发生在 `NavigationView` 的内容区域内。
- 内容宿主必须裁切越界内容，滑入页面不得覆盖左侧导航、标题栏或底部播放器。
- 不改变现有颜色、圆角、阴影、页面布局和数据展示。
- 不叠加淡入、缩放或旋转；页面只做水平位移。
- 旧页面保持可见，直到新页面完全覆盖它。

## 架构

在 `ShellPage` 的内容区域引入专用双层导航宿主：

- `CurrentFrame`：承载当前可见页面，转场期间保持静止。
- `IncomingFrame`：承载目标页面，初始位于内容区右侧，转场结束后成为新的 `CurrentFrame`。
- `QueuePane`：继续位于页面宿主上层，不进入两个 Frame 的转场逻辑。

两个 Frame 交替承担 current/incoming 角色，避免每次导航重建 XAML 容器。新页面完成导航、Loaded 和首轮布局后才开始位移，以免空白页面滑入。

## 导航流程

1. 将 route 解析为目标 Page 类型。
2. 如果目标类型与当前类型相同，只同步导航选中态并结束。
3. 在空闲 Frame 中导航到目标页面，并保持在宿主右侧。
4. 等待目标 Frame 完成首轮布局。
5. 暂时阻止两个页面内容的指针和键盘输入。
6. 通过合成位移动画将目标 Frame 从 `X = host.ActualWidth` 移动到 `X = 0`。
7. 动画完成后清空旧 Frame，将目标 Frame 设为当前 Frame，并恢复输入和焦点。

页面 ViewModel 和应用级服务继续沿用现有生命周期；转场宿主只负责页面视觉层和导航并发，不接管业务状态。

## 连续导航

导航宿主持有单调递增的 transition revision 和一个最新目标请求：

- 动画期间收到新导航时，立即把当前进入页落位并完成旧转场。
- 清理更旧的页面层和事件订阅。
- 丢弃中间请求，只执行最后一次导航请求。
- 最新目标重新从右侧执行完整 280ms 转场。

任何过期的 Loaded、布局或动画完成回调都必须核对 revision，不得修改当前页面。

## 窗口与异常处理

- 动画期间窗口尺寸变化时，立即完成当前转场，再按新宽度处理后续导航。
- 如果目标页面导航失败，保留旧页面并恢复输入状态，记录 `navigation.cover.failed` 日志。
- 如果内容宽度暂时为零，等待下一次有效布局；若宿主已卸载则取消请求。
- Shell 卸载时停止动画并解除 Frame 事件订阅。

## 可测试性与验收

- XAML 契约测试确认双 Frame、裁切容器和 QueuePane 层级。
- 导航协调器单测覆盖首次启动、同页导航、正常完成、连续点击只保留最新请求、过期回调和尺寸变化。
- 实机日志覆盖 `requested`、`prepared`、`started`、`completed`、`superseded` 和 `failed`。
- 在 Home、Search、Library、Albums、Artists、Favorites、HITS、Settings 及至少一个详情页之间逐项切换。
- 用连续截图验证旧页面保持静止、新页面从右侧进入、最终无残留层。
- 验证 1280、1440、1600、1920 宽度下无越界、黑屏、页面堆叠或播放器位移。

## 非目标

- 不修改页面业务逻辑或数据加载策略。
- 不重新设计页面、导航栏或底部播放器。
- 不为弹窗、QueuePane、菜单或播放器状态增加覆盖式转场。
- 不实现基于导航顺序的左右方向变化，也不为返回操作使用反向动画。
