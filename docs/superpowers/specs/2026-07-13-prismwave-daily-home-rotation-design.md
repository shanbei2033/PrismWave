# PrismWave 每日首页跨天轮换设计

## 目标

让每天发布的 PrismWave 首页在以下模块中保持明显变化，并优先保证与前一天不重复：

- 今日趋势 / 全球热门
- 可直接播放
- 频道探索
- 流派探索

首页数据仍由 `prismwave-hits` 生成和发布。WinUI 与 Flutter 客户端继续消费 schema 8 JSON，不在客户端临时随机改写榜单。

## 当前行为

`scripts/build_home.py` 会按北京时间日期设置随机种子，并在单次生成中限制同一歌手的数量和相邻距离。它不会读取历史首页，因此同一首高分歌曲可以连续多天出现在相同或不同模块。

每日历史文件已经以 `home/home_recommendations-YYYY-MM-DD.json` 形式保留，能够直接作为跨天轮换输入，不需要新增数据库或在线服务。

## 方案选择

采用“昨日硬排除、近 7 天递减惩罚、候选不足最小回补”的生成端轮换策略。

不采用纯客户端随机，因为不同设备会看到不同内容，缓存和问题复现也会变得困难。不采用永久不重复，因为候选最终会耗尽，且会持续降低榜单相关性。

## 历史模型

生成当天首页前，读取当天之前最多 7 份有效 schema 8 归档：

```text
home/home_recommendations-YYYY-MM-DD.json
```

歌曲身份沿用生成器已有的 `track_identity()`，即对歌曲名和歌手名标准化后组合。历史读取同时覆盖 `topPlaylist.tracks` 和全部 `sections[].tracks`，因此歌曲即使昨天出现在另一个模块，今天也会被识别为重复。

历史结果组织为：

- `yesterday_keys`: 昨日首页中出现过的全部歌曲身份。
- `recent_age_by_key`: 最近 2–7 天出现过的歌曲及距今天数。
- 无效、缺失或非 schema 8 的归档被忽略并记录诊断，不中断生成。

## 选曲规则

### 昨日硬排除

构建 Top 100 和每个 section 时，先从候选集中排除 `yesterday_keys`。只要新鲜候选足够，最终结果与昨日首页保持零歌曲交集。

这是全首页级排除，不只是同名 section 之间比较，避免歌曲从“全球热门”移动到“环球榜单”后仍被用户视为重复。

### 近 7 天降权

最近 2–7 天出现过的候选不完全删除，而是在 `diverse_candidate_score()` 中增加历史惩罚：

| 距今天数 | 选择惩罚 |
| --- | ---: |
| 2 天 | 0.24 |
| 3 天 | 0.18 |
| 4 天 | 0.13 |
| 5 天 | 0.09 |
| 6 天 | 0.05 |
| 7 天 | 0.02 |

榜单原始分数、来源权重、歌手数量限制和歌手间隔规则保持不变。历史惩罚只影响同批候选之间的选择优先级。

### 候选不足回补

网络或数据源故障时，严格排除可能导致 Top 100 不足或某个 section 消失。生成器按以下顺序回补：

1. 使用未在昨日出现的新鲜候选。
2. 使用最近 2–7 天出现、但昨日未出现的候选。
3. 仅在仍达不到目标数量时，从昨日候选中按原始综合排名回补最少数量。

因此正常数据量下昨日重合为 0；异常情况下优先保证首页仍能生成，同时把实际重合数量暴露在诊断信息中。

## 各模块行为

### 今日趋势和全球热门

Top 100 与 `global-hot` 都使用全首页历史轮换。真实趋势分数仍决定新鲜候选的先后顺序，但昨天展示过的热门歌至少休息一天。

### 可直接播放

继续要求候选具有有效 `audio_url`。在可播放候选池内执行相同轮换，不能为了去重放入不可播放歌曲。

### 频道探索

`world-charts`、`listener-trends` 和 `audius-trending` 分别保留现有来源过滤，再执行历史排除和降权。WinUI 当前只显示其中部分频道；生成数据仍对全部频道应用轮换。

### 流派探索

所有 `style-*` section 保留来源标签过滤和同日跨流派去重，并叠加跨天历史轮换。窄流派候选不足时允许最小回补，但不能低于现有 `MIN_SECTION_TRACKS`。

## 发布诊断

schema 版本保持为 8，新增可选根字段 `rotationSnapshot`：

```json
{
  "historyDaysLoaded": 7,
  "yesterdayTrackCount": 286,
  "previousDayOverlapCount": 0,
  "recentReuseCount": 18,
  "fallbackReuseCount": 0
}
```

旧客户端会忽略该字段，不需要同步升级。工作流日志同时输出各 section 的昨日重合数，方便发现数据源退化。

## 代码边界

改动属于独立仓库 `shanbei2033/prismwave-hits`：

- 修改 `scripts/build_home.py`：历史读取、历史惩罚、分阶段回补、诊断输出。
- 修改 `tests/test_build_home_diversity.py`：覆盖昨日排除、7 天惩罚、候选不足回补、确定性输出。
- 保持 `.github/workflows/build_home.yml` 的每日调度和发布方式不变。
- PrismWave WinUI/Flutter 客户端不需要业务代码变更。

## 测试与验收

自动测试必须覆盖：

1. 候选充足时，今天 Top 100 与昨日首页零交集。
2. `streamable-now` 轮换后仍全部具有 `audio_url`。
3. 近 2 天歌曲比近 7 天歌曲受到更高惩罚。
4. 同一日期和相同历史输入生成结果完全确定。
5. 候选不足时只回补达到目标数量所需的最少昨日歌曲。
6. 缺失或损坏历史归档不会阻断生成。
7. 现有歌手数量、歌手间隔和北京时间副标题测试继续通过。

发布前用连续两个测试日期运行生成器，并比较 Top 100、所有频道和所有 `style-*` section。正常候选规模下，每个模块与前一天的歌曲交集应为 0，`rotationSnapshot.previousDayOverlapCount` 应为 0。

## 风险与取舍

- 严格昨日排除会让“全球热门”变成经过轮换的热门推荐，而不是完全忠实复制单一平台榜单；这是满足每日不重复所接受的产品取舍。
- GitHub Actions 或上游平台失败时可能触发最小回补。诊断字段必须让这种情况可观察，不能静默伪装成完全轮换成功。
- 不修改 `track_identity()` 的标准化规则，避免历史身份与当前去重身份不一致。
- 不永久保存独立状态；归档 JSON 是唯一历史来源，便于复现和回滚。
